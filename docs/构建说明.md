# Cap 中文汉化 — 说明与构建指南（v3）

> 目标软件：**Cap**（github.com/CapSoftware/Cap）——Rust + GPUI 原生桌面录屏工具，官方发布版即 `apps/desktop-gpui`。
> Cap **没有国际化框架**，界面英文全部硬编码在源码里；本次汉化的做法是**把这些硬编码字符串直接精确替换为中文**，不引入 i18n 依赖，因此不需要改任何构建配置。
> 基线：`main` 分支（commit `8a14802`）。

## 三、构建步骤

一键脚本（本机已写好）：`bash build.sh [1|2|3|4]`，不传参数则全部依次执行。

```bash
bash build.sh 1   # cap-setup：解压原生依赖、生成 .cargo/config.toml
bash build.sh 2   # 编 cap-muxer / cap-cli / cap-exporter（Rust 1.88）
bash build.sh 3   # 编 GPUI 主程序 Cap.exe（Rust 1.95）——最耗时
bash build.sh 4   # Tauri 打包成 NSIS 安装程序
```

产物：`cap-build/apps/desktop-gpui/target/x86_64-pc-windows-msvc/release/bundle/`
- `nsis/Cap_0.6.1_x64-setup.exe` ← **推荐用这个安装**
- `msi/Cap_0.6.1_x64_en-US.msi`（备选）

> 首次全量编译约 **40–70 分钟**（GPUI 依赖树极大）；之后只改界面文案的增量重编约 **8–15 分钟**。

### 打包参数的两处必要调整（本机环境，已改在 `cap-build/apps/desktop-gpui/tauri.conf.json`）

1. `bundle.windows.nsis.compression`: `lzma` → **`bzip2`**
   原因：NSIS 的 makensis 是 32 位程序，用它默认的 SOLID lzma 压缩约 180 MB 载荷时**确定性报错**
   `Internal compiler error #12345: deflateInit() failed`；换 bzip2 后一次通过（体积略大）。
2. `bundle.createUpdaterArtifacts`: `true` → **`false`**
   原因：该选项要用 Cap 官方私钥给更新包签名，本机没有私钥，会以
   `A public key has been found, but no private key` 收尾报错（安装包其实已生成）。
   我们不需要自动更新签名件，关掉即可。

## 四、安装与使用

1. 双击 `Cap-0.6.1-zh-cn-x64-setup.exe` 安装（与官方安装包同流程，可覆盖安装官方版）。
2. 首次启动会要摄像头/麦克风/屏幕录制权限，按提示允许即可。
3. 界面为简体中文；Cap 自身**没有**语言切换开关，中文是编译进二进制的。
4. 已安装过官方 Cap 的话，两者是同一个产品标识（`so.cap.desktop`），安装中文版会替换它。

## 五、汉化维护方式（要继续扩范围时看这里）

汉化走「**扫描 → 审计 → 字典 → 精确替换 → 语法校验**」流水线。全部脚本在项目根目录（交付副本在 `汉化工具/`）：

| 脚本 | 作用 |
|---|---|
| `join_literals.js` | 把 `\`+换行 折行的跨行字面量合并成单行（Rust 语义等价），否则逐行替换匹配不到 |
| `scan_strings2.js` | 扫描源码里所有英文字符串候选，输出 `scan_v*.txt` |
| `audit_dict.js` | **全树用法审计**：对每条候选在全仓库找全部出现位置，判定 `[SAFE]/[LOGONLY]/[TESTMIX]/[TESTONLY]/[RISK]` |
| `split_audit.js` | 按文件拆分审计结果，生成 `audit/<文件>.txt`（作业包）与 `edge-review.txt`（边缘项） |
| `apply_dicts.js` | 把 `dict/*.json` 应用到 `cap-zh/`，支持 `[英文, 中文, 行号]` 三元素精确锁定 |
| `verify_dict.js` | 字典自检：原文能否找到、占位符一致、禁译清单、RISK 拦截、同文件同原文多译文 |
| `blacklist.txt` | 禁译清单（审计器抓不到的：窗口标题、字体/模型名、配置键、键盘码、单字母…） |
| `edge-allow.txt` | 人工批准的 TESTMIX/RISK 例外清单 |
| `check_syntax.sh` | 用 rustfmt 解析全部文件，揪出「翻译破坏了字符串字面量」的语法错误 |
| `gen_inventory.js` | 按 `orig/` 与 `cap-zh/` 的真实逐行差异生成 `Cap汉化字符串清单.md` |

### 关键判据（v3 新增，务必沿用）

1. **测试区里出现过的串一律不译**（`TESTMIX`）。原因：测试期望值常把该串作为**更长字面量的子串**嵌入，只译源码侧会静默弄红测试。
   这条规则顺带自动挡住了全部窗口标题（`app_windows.rs` 里有断言表）。
2. **`match 键` / `==` 比较 / `contains()` / `key:` 赋值** 位置的串不译（`RISK`）。
3. **审计器抓不到的必须靠 `blacklist.txt` 兜底**：字体名、模型名、camelCase 配置键、大写单字母、窗口标题。

### 踩过的真坑（务必记住）

1. `settings_pages.rs` 的快捷键映射 `"delete" => "Delete"`：右侧返回值是键盘码，被误译成中文会破坏 Delete 键映射；
2. `editor_tabs.rs` 的 `FONT_OPTIONS`：字体名既显示在界面、又写入配置，必须与前端默认值一致；
3. `settings_window.rs` 的 `format_project_name()`：`.replace("{target_kind}", "Window")` 有测试断言 `starts_with("Safari (Window) ")`，译了会红测试；
4. **同一个英文串在不同文件/不同行可能是两种含义**（如 `store.rs` 的 `"Light"`：摄像头模糊档位「轻度」vs 主题「浅色」）→ 必须用三元素 `[英文, 中文, 行号]` 分开处理。
5. 「译了没生效」不一定是编译问题：候选去重是**按字面量+首个文件**做的，同一个串出现在多个文件时只有第一个文件被译 —— 必须**多轮扫描**直到收敛（v3 一共跑了 3 轮：v3→v5→v6）。
